# 📐 Agent 技能编写规范（skill-authoring-guide）

> 给 LLM Agent 的技能编写与维护规范：TDD 流程、简练语言、锐利判断锚点、冷跑验收、部署前检查。
> A writing & maintenance guide for LLM agent skills: TDD workflow, concise language, sharp judgment anchors, cold-run acceptance, pre-deployment checks.

**作者：** [w-weixiao](https://github.com/w-weixiao) · **协议：** MIT · **语言：** 简体中文 + English

## 🎯 一句话概括：它能干什么

帮你把 LLM Agent 的**技能库从"越写越长、越写越屎山"管回"模型只看文档就能做对判断"**。

不是教你写某一个技能的内容，而是一套**编写规范 + 验收流程**——管"技能该长什么样、该按什么顺序改、改完怎么证明没写偏"。

## 🔥 碰到的痛点

技能库一旦多起来，几乎人人都会撞上这几堵墙：

- 📈 **越写越长**：因果解释、背景铺垫、冗余条款堆满，正文动辄几百行，token 烧得起，模型读不完。
- 🌀 **判断锚点太糊**：写着"参数=配方""见配方"这种转指句，模型零上下文时只能靠脑补，偏了还不一定报得出。
- 🧯 **没有验收标准**：改完一版没人知道哪版真验证过，`cold_run` 字段要么缺、要么版本对不上，等于没验。
- 🎲 **全库规模失控**：25 个技能一全库扫，触发词窄的、纯动作无场景的、超体量的混在一起，不知道哪些该修哪些该留。

## ❄️ 冷跑：原理与作用

冷跑（cold-run）是本规范的核心验收手段，也是和"我读了文档觉得没问题"最大的区别——它用**一个零上下文的子代理**代替"编写者自己再读一遍"，来证明"只看文档的模型不会跑偏"。

**原理（怎么跑）**：

1. 起一个零上下文子代理（Hermes 里是 `delegate_task`，Claude Code 里是新的 subagent / 新会话），**只喂技能文档本身**，不喂任何背景、对话历史、你脑子里的理解。
2. 让它照文档执行一次典型任务，回报走了哪条分支、敲了哪些命令、哪句文档让它不确定。
3. 你把它的回报和你的编写意图逐条对读：读歧义、跳步、自创规则、漏读导航行，任一命中即"偏差"。
4. 有偏差就回正文把该处写成显式判断逻辑（"遇 X 按 Y 因为 Z" + 边界 case），再冷跑一次。
5. **两连过才算收工**：连续两次零偏差才合格；中间任一次有偏差，计数归零重新来。

**作用（为什么非跑不可）**：

- 🧠 **验证"模型只看文档会不会偏"**：你读文档时脑子里带着编写时的上下文，模型没有——冷跑补的就是这个差。
- 🔍 **定位"哪句文档模糊"**：偏差会精确指到某一行，改的是判断锚点本身，不是加死规则堵漏。
- 📝 **留下"哪版验过"的证据**：通过后把版本+日期+方式回填 frontmatter 的 `cold_run` 字段；正文一改、version 一升，旧记录自动失效，必须重冷跑。
- 🧪 **给审计留接口**：全库审计只读 `cold_run` 字段判断哪些技能冷跑过、哪些需补跑，不重跑（分工见配套技能节）。

> 一句话：冷跑 = 用零上下文子代理替"没带上下文的你"读一遍文档，证明文档本身够锐利。

## 🌟 用了以后的效果（一般结论）

按本规范跑完之后：

- ✅ 模型**只看文档就能把判断做对**（零偏差冷跑）——这是"给方向不给答案"的直接收益。
- ✅ 全库规模不失控：体量、路由、触发词都在上限内，不滚成屎山。
- ✅ 每版改完都有 `cold_run` 记录"哪版验过"，下一版一升旧记录自动失效，不会拿过期结论当现行。

## 📋 更新说明

**v2.8.0（2026-09-27）**
- 🔴 新增【红线】：description 上限由 200 字收紧为 **≤60 字**——开机时技能索引每条描述实际只注入前 60 字（`SKILL_PROMPT_DESC_LIMIT`），超限部分被截断、后半触发词开机不可见，路由静默失效；核心触发词（何时用 + 何时别用）必须全部落在 60 字内。
- 🔁 升版规则扩大：原"正文改动必升 `version`" → 现"**内容**改动（正文或 frontmatter 的 description）必升 `version`"；只改 description 补触发词也算内容改，旧 `cold_run` 随之失效，需重冷跑再回填。
- ✅ 部署前检查同步：结构校验的"description ≤200 字"改为"≤60 字【红线】"。
- ❄️ 两轮零偏差冷跑通过：60字红线 / 150字改法 / 触发词布局 / version+cold_run 失效 / 冷跑归编写侧 5 问全对；Q4 缺口经锚点修补后两连过。

## 🚀 安装 / 别人怎么用

把这个仓库 clone 下来后，**把子目录拷进你 agent 的技能目录**即可（`SKILL.md` 在子目录里，不是仓库根）：

```bash
git clone https://github.com/w-weixiao/agent-skills
# Claude Code
cp -R agent-skills/skill-authoring-guide ~/.claude/skills/
# Codex / Gemini CLI / Copilot（跨运行时）
cp -R agent-skills/skill-authoring-guide ~/.agents/skills/
```

之后重启或重载 agent 使其被发现。本技能假定你的 agent 运行时支持文件式技能。

**能被搜到吗 / 要不要放什么分支下**：仓库是 **PUBLIC**、默认分支 `master`，按 `w-weixiao/agent-skills` 直接搜仓库可命中；GitHub 代码全文搜索对新推仓库有几分钟到几小时的索引延迟，属正常。agent 运行时发现技能靠的是**目录结构 + `SKILL.md` 文件名**（不是 Git 分支），所以分支叫 `master` 还是 `main` 不影响别人使用，按你 agent 约定放对目录即可。
